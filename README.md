## 为什么这个东西不会又是「提示词汇编」

| | 常见的「去 AI 味」prompt | 这个 skill |
| --- | --- | --- |
| 输出 | 一段改写后的文字 | 分数 + 六个维度 + 逐句证据 + 改写 |
| 判断 | 靠模型自己说「更像人了」 | 确定性脚本，同一输入永远同一分数 |
| 可比较 | 不能 | 改前改后可以量化，能进 CI |
| 可解释 | 不能 | 每个扣分点都指向具体词、具体句 |
| 误判 | 无法自查 | 引号里的引用不扣分；`--mode doc` 排除技术文档的正当结构 |

**它是个量具，不是一个 prompt。**

## 安装

```bash
git clone https://github.com/zhbehx/ai-tell.git ~/.claude/skills/ai-tell
```

## 用法

```bash
# 基础检测
python scripts/ai_tell.py draft.md

# 看证据：到底是哪几句露了馅
python scripts/ai_tell.py draft.md --explain

# 卡住不让发：超过 60 分退出码 1
python scripts/ai_tell.py draft.md --fail-over 60

# 技术文档模式（小标题/列表不计入扣分）
python scripts/ai_tell.py README.md --mode doc

# 管道输入
pbpaste | python scripts/ai_tell.py -

# 结构化输出
python scripts/ai_tell.py draft.md --json
```

退出码：`0` 正常 / `1` 触发 `--fail-over` / `2` 文件错误或文本过短。

## 六个维度

| 维度 | 权重 | 抓什么 |
| --- | --- | --- |
| 套话黑话 | 24% | `赋能`、`闭环`、`抓手`、`颗粒度`、`底层逻辑`、`降本增效` |
| 空转收尾 | 22% | 「希望对你有所帮助」「让我们一起」「综上所述」 |
| 对称句式 | 16% | 不是…而是…／不仅…而且…／一方面…另一方面… |
| 结构模板 | 14% | 前言/背景/总结、等长分段、列表占比过高 |
| 抽象大词 | 14% | `至关重要`、`深远影响`、`极大提升`、`充分发挥` |
| 句长均匀 | 10% | 句长变异系数 < 0.40（机器节拍器） |
| 具体性缺失 | 14% | 每千字数字/日期/引号原话不足 |

**分档**：≥75 一眼 AI ｜ 60–74 很像 AI ｜ 40–59 有点味 ｜ 20–39 基本像人 ｜ <20 很有人味

## 七个改写动作

按性价比排序，详见 [`references/rewrite-playbook.md`](./references/rewrite-playbook.md)（含 30 组对照）：

**删**（删空转句）→ **换**（黑话换成动作）→ **减**（对称句留一半）→ **破**（打掉句长节拍器）→ **添**（每 150 字加一个具体物）→ **挪**（先场景后结论）→ **留**（承认一次判断错误）

最难伪造的是最后一个。AI 会写「我也曾遇到挑战」，人会写「我第一版做错了，赔了 4 万」。

## 我们把自己也测了一遍

这个 README 第一次跑出来是 **48.6 分**（doc 模式）。原因很具体：文里列举了「赋能」「闭环」「抓手」这些要被检测的词，脚本把它们当成了「你在用这些词」。

于是做了两件事，都是产品级修复而不是调分数：

1. **加引号遮蔽**：引号、书名号、行内代码里的内容不参与统计（引用 ≠ 使用）。
2. **文档里列举术语时用反引号标出来**，读者也知道那是术语而不是我的口头禅。

现在本仓自测：

```
$ python scripts/ai_tell.py README.md --mode doc
AI 味：2.2 / 100    很有人味：细节密度和节奏都自然
```

**校准没有被这次修改影响**：AI 稿仍是 85.1，人写稿仍是 0.0。CI 里有断言守着这两个数（`ai >= 75`、`human <= 20`、差值 `>= 50`）。

## 和写作类 skill 怎么配合

- 先用 [`viral-copy`](https://github.com/zhbehx/viral-copy) 出稿（结构、钩子、标题）。
- 再用本仓测一遍（语言是不是像人写的）。
- 前者管「有没有人愿意看」，后者管「看完觉不觉得你在糊弄」。

## 三个诚实的局限

1. **它测语言特征，不测内容价值。** 0 分也可能是一篇废话。
2. **它不认生僻写法。** 有意打破节奏的实验文本可能被误判——看证据，别只看分数。
3. **词库是中文优先的。** 英文文本只对「句长均匀」「具体性缺失」有效。欢迎 PR 补英文模式。

## 自定义

1. **加你们行业的黑话**：`scripts/ai_tell.py` 顶部 `JARGON` 列表，加一个词就生效。
2. **调权重**：`WEIGHTS` 里改，`article` 与 `doc` 两套独立。
3. **加维度**：照着 `score_jargon` 写一个返回 `(0–100, 证据列表)` 的函数，加进 `analyze`。

## FAQ

**Q：0 分是不是就完美了？**
A：不是。0 分只代表「没有明显的模板痕迹」。文章好不好，还得看有没有值得转发的信息。

**Q：为什么引号里的词不算？**
A：引用「赋能」和真的用「赋能」是两件事。脚本会先遮蔽引号、书名号、行内代码里的内容再统计。

**Q：技术文档分数高怎么办？**
A：加 `--mode doc`。小标题和列表是文档的必需品，不该被当成 AI 味。
